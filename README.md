# Objectives Mapper

A single-page application that visualises how individual team members' personal objectives connect to business objectives. Open `index.html` in any browser — no server or build tools required.

![Objectives Mapper screenshot](screenshot.png)

---

## How it works

Business objectives are displayed as fixed boxes in the centre of the page. Each team member's personal objective cards appear on the left or right side, connected to their linked business objective by a coloured arrow.

**Interacting with the map:**
- **Drag** any personal objective card to reposition it — arrows follow in real time
- **Click** an engineer's name in the top legend to toggle their cards and arrows on/off
- **Click "All"** to restore everyone
- **Hover** over a card to read the full SMART objective text in a tooltip

## Changing the data

All data lives in `objectives.yaml`. Edit this file to update business objectives, add/remove engineers, or change personal objectives.

### File structure

```yaml
business_objectives:
  - objective_id: BO1         # unique ID used to link personal objectives
    name: ...
    summary: ...

software_engineers:
  - name: Person A
    role: Senior Software Engineer
    personal_objectives:
      - name: Implement distributed tracing
        smart:
          specific:   ...
          measurable: ...
          achievable: ...
          relevant:   ...
          time_bound: ...
        linked_business_objective: BO1   # must match an objective_id above
```

### Adding a new engineer
1. Append a new entry under `software_engineers` in `objectives.yaml`
2. Give each of their personal objectives a `linked_business_objective` that matches an existing `objective_id`
3. Regenerate `index.html` (see below)

### Adding a new business objective
1. Append a new entry under `business_objectives` with a unique `objective_id`
2. Reference it in any personal objective's `linked_business_objective`
3. Regenerate `index.html`

## Regenerating index.html with Claude

After editing `objectives.yaml`, ask Claude Code to sync the changes into `index.html`:

```
Update index.html to take into account changes from objectives.yaml
```

Claude will diff the YAML against the embedded `DATA` constant in `index.html` and apply all necessary updates — new engineers, renamed fields, changed objectives, new SMART breakdowns, layout offsets for additional columns, and new SVG arrow markers.

### Other useful prompts

| Goal | Prompt |
|---|---|
| Add SMART breakdowns for new objectives | `Update objectives.yaml so each personal objective has a SMART breakdown. Update index.html to pull the SMART data from each person's personal objective` |
| Rewrite objectives to be more specific | `Rewrite the personal objectives for [Person X] to be more specific and measurable` |
| Change the colour scheme | `Update the colour scheme in index.html to use [your palette]` |
| Add a new feature | Describe what you want — e.g. `Add a progress indicator to each personal objective card` |
